# Локализация Converter и страницы проекта

Статус: предложение для согласования. Реализация, сборки и публикация этим документом не запускаются.

## Цель

Сделать приложение и страницу проекта доступными на русском и английском языках. Дать каждому языку свою ссылку поддержки и сохранить существующее поведение конвертации, истории и обновлений.

## Требования пользователя

- Первые языки: русский (`ru`) и английский (`en`).
- При автоматическом выборе использовать основной язык системы. Если он поддерживается, выбрать его; иначе выбрать английский. Вторичные предпочтительные языки не подменяют основной.
- Страница проекта на GitHub Pages также должна поддерживать оба языка.
- Ссылка поддержки зависит от языка. Русская: `https://pay.cloudtips.ru/p/7e782291`. Английский сервис пока не выбран: английские элементы поддержки скрыты.
- Сначала согласовать план, затем приступать к реализации.
- Целевые сборки: macOS Apple Silicon и Windows x64. Intel macOS и мобильные сборки в эту работу не входят.

## Предлагаемое поведение

### Выбор языка приложения

На первом запуске действует режим `system`. Основной системный тег приводится к базовому языку без учёта регистра: `ru-RU` → `ru`, `en-US` → `en`, `de-DE` → `en`. Если определить язык не удалось, применяется `en`.

В «О программе» добавить глобальный переключатель с неизменным двуязычным названием «Язык / Language». Варианты: «Системный / System», «Русский», «English». Ручной выбор сохраняется между запусками и имеет приоритет над системным. Выбор `system` сразу повторно определяет основной язык ОС; затем он определяется при каждом запуске. Отслеживание изменения языка самой ОС посреди сеанса не требуется.

Переключение применяется без перезапуска приложения и без перезапуска задач. Меняются подписи, открытые диалоги, доступные новые предупреждения, форматирование и принадлежащие приложению нативные пункты меню. Выбор языка не входит в настройки отдельной конвертации.

### Объём перевода

Перевести интерфейс Vue, подсказки и доступные имена элементов, подписи PrimeVue, состояния задач и скачивания, уведомления об обновлении, настройки, ошибки и предупреждения новых задач, собственные заголовки файловых диалогов, пункт «О программе» и текст подготовки GitHub issue.

Стандартные кнопки системного файлового диалога остаются под управлением ОС. Содержимое словарей, их названия, пути, языки статей и исходные технические подробности сторонних ошибок не переводятся. Выбранный язык интерфейса не влияет на содержимое MDX/MDD, выбор головного словаря и алгоритмы конвертации.

Числа и множественные формы зависят от языка. Русские единицы сохраняются: `байт`, `Кб`, `Мб`, `Гб`, `Тб`; английские: `bytes`, `KB`, `MB`, `GB`, `TB`. Расчёт размеров приложения сохраняет основание 1024, сайта — существующее основание 1000. Проценты скачивания остаются целыми.

### Ошибки, предупреждения и история

Существующие коды ошибок недостаточны для перевода: один код используется для разных текстов. Добавить необязательные `message_key` и `message_args` к сериализованным сообщениям; оставить существующие поля `code`, `message`, расположение в источнике, серьёзность и число повторений.

Новые сообщения отображляются через каталог текущего языка. Старые записи без ключа показывают сохранённый `message`. Старые журналы не переписываются, повторная конвертация для просмотра истории не нужна. Нельзя надёжно восстановить перевод всех старых сообщений по одному коду; перевод русских строк регулярными выражениями не применяется.

Группировка новых предупреждений использует код, источник и структурированные параметры, а не локализованную строку. Количество групп и повторений не зависит от языка. Для сырого JSON-отчёта сохраняется совместимый `message` и добавляются ключ/параметры; язык интерфейса не переписывает уже созданные отчёты. CLI получает совместимые дополнительные поля, отдельный переключатель языка CLI в эту работу не входит.

### Ссылки поддержки

Общий `config/locales.json` содержит поддерживаемые языки и `support_url` каждого языка. Приложение и генератор сайта используют этот источник. В `ru` видны нынешние иконка в шапке и ссылка «Сказать спасибо»; в `en`, пока URL равен `null`, обе отсутствуют, также отсутствуют ссылки поддержки в шапке и подвале сайта.

Tauri открывает адрес из своей конфигурации по текущему языку; произвольный URL из интерфейса для этой команды не требуется. Нет определения страны по IP. После появления зарубежного сервиса достаточно изменить конфигурацию: сайт получит адрес при следующей публикации, приложение — в следующей сборке. Уже установленные приложения не загружают платёжные настройки удалённо.

### Страница проекта

Сгенерировать две полноценные статические страницы: `/converter/ru/` и `/converter/en/`, с явным переключателем «Русский / English». Существующий корневой `/converter/` остаётся рабочим входом. При открытии корня небольшой локальный скрипт выбирает сохранённый пользователем язык сайта либо основной `navigator.language`: поддерживаемый язык открывает соответствующую страницу, неподдерживаемый — английскую. Не перебирать вторичные языки браузера. Веб-страница не имеет надёжного доступа к основному языку ОС, поэтому использует основной язык браузера.

Явный языковой URL имеет приоритет и не перенаправляется. Переключатель запоминает выбор сайта независимо от настройки установленного приложения. Если localStorage недоступен, переход всё равно работает; если JavaScript выключен, корневая страница содержит полноценный английский вариант с переключателем и установщиками. Canonical корня указывает на `/converter/en/`.

Использовать общий HTML-шаблон и стили, отдельные текстовые каталоги сайта, корректные `lang`, метаданные, `canonical`, `hreflang` и переведённые подписи изображений. Сохранить пользовательские правки текущей страницы. Для английской страницы подготовить снимок английского интерфейса из тестового сценария с синтетическими данными.

Обе страницы берут одну версию и одни установщики последнего стабильного релиза. Существующее обновление через GitHub Actions сохраняется; изменение общих языковых настроек также запускает публикацию сайта. Ссылки скачивания доступны без JavaScript и без авторизации посетителя.

## Архитектура

Рекомендуется Vue I18n для Vue, общие JSON-каталоги приложения для Vue и Tauri, структурированные сообщения Rust и статическая генерация сайта из собственных каталогов. Переводы входят в поставку и работают офлайн. Для определения основного языка ОС использовать `sys-locale` в Tauri до создания меню. PrimeVue обновляет свою locale вместе с Vue I18n; обновлять PrimeVue ради этой функции не требуется.

Альтернативы: собственный переводчик уменьшит число зависимостей, но потребует самостоятельно поддерживать формы слов и реактивность; перевод только во Vue оставит нативные сообщения на русском. Рекомендуемый вариант покрывает оба слоя без сетевого сервиса переводов.

Настройку языка сохранять отдельно от задач в `app_config_dir/preferences.json` с атомарной записью. Повреждённый файл не должен мешать открытию приложения: использовать режим `system`, сохранить повреждённую копию до следующей записи. Ошибка ручного сохранения должна быть видна; интерфейс не сообщает об успешном сохранении, если запись не удалась.

## Критерии приёмки

1. Чистый запуск на `ru-RU` даёт русский интерфейс; на `en-US`, `de-DE` или неизвестной локали — английский.
2. Ручной выбор переживает перезапуск; возврат к `system` снова использует основной язык ОС.
3. Переключение при активной задаче не меняет её состояние, прогресс, результат и число предупреждений.
4. Новые ошибки и предупреждения доступны на обоих языках; старая история открывается с исходным текстом там, где нет ключей перевода.
5. Английский интерфейс и сайт не показывают CloudTips или пустую ссылку поддержки. Русские элементы открывают прежний адрес.
6. Обе версии сайта содержат одинаковый актуальный номер релиза и корректные прямые ссылки DMG Apple Silicon / EXE Windows x64. Корень выбирает основной язык браузера с fallback `en`; явные языковые URL не меняют язык автоматически.
7. Интерфейс остаётся пригодным при 740×500 и 540×400, в обеих системных темах; длинные пути, названия и переводы не перекрывают управление.

## Проверка и поставка

Выполнить модульные проверки, тесты совместимости контрактов, браузерные сценарии на обоих языках и темах, Rust-проверки и Windows CI. После реализации сначала подготовить macOS Apple Silicon для проверки пользователем. Публикация сайта и нового релиза — после отдельного разрешения пользователя. Существующая автоматическая смена patch-версии при сборке сохраняется; minor/major меняются только по прямому указанию.
