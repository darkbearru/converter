# Приёмка загрузки и URL-конвертации

18 октября 2026, macOS ARM64, Rust 1.99.1. Нативные тестовые HTTP-серверы работают на loopback без CORS-заголовков; запросов HEAD нет.

Контрольная передача: 2 097 152 байт (значение каждого байта — 9). Первый GET получает `200`, `Content-Length: 2097152`, `ETag: "fixture-v1"`; соединение обрывается после 1 048 576 байт. Сохранена контрольная точка 1 048 576. Второй GET отправляет `Range: bytes=1048576-`, `If-Range: "fixture-v1"`, `Accept-Encoding: identity`; сервер возвращает `206`, `Content-Range: bytes 1048576-2097151/2097152`, длину 1 048 576. Исходный SHA-256 и SHA готового файла совпали: `131fca71fe404a1b870c8d84b020c32e2ffc1d0a6e686e71be976266b0207f17`. Фактический журнал тестового сервера содержит ровно два GET с указанными headers; Cookie и Authorization отсутствуют.

Отдельные тесты проверили паузу, пересоздание manager/cache и продолжение; отмену; повреждение порции и готового тела перед SHA; неподтверждённый хвост; сбои до/после sync и замены манифеста; исчерпание места через fault injection; блокировку второго writer. Для `200`, `416`, нового/слабого/отсутствующего ETag результат содержит одну полную версию, а не склейку. Неправильный диапазон, HTTP encoding и превышение размера отклоняются.

Проверены 403, три дополнительных повтора 503/429, `Retry-After` как число и HTTP-дата, пауза при ожидании больше пяти минут. Прерывание ожидания проверено с остановленным временем Tokio. Неизвестный размер даёт байты без процента. Готовый файл повторно проверяется без GET.

CLI-тест удерживает ответ ZIP ресурсов, когда основной DSL уже готов: событий `phase: conversion` и папки результата ещё нет. После получения ресурсов создаются MDX/MDD, независимый `mdictlib 0.2.8` извлекает картинку с исходным SHA-256. Затем оба HTTP-сервера останавливаются, повторная конвертация успешно использует кэш. URL содержит `secret-token` в query; stdout/stderr его не содержат. HTML по ссылке возвращает `download_is_html` и не публикуется.

CI кэша и правил HTTP (`512ee8d`, run 39106729328) прошёл на macOS и Windows. Полная проверка transfer/CLI (`6a82f01`, run 39107269006) тоже прошла на macOS и Windows. Физическое заполнение системного диска не выполнялось; ошибки сохранения моделируются в тестах.
