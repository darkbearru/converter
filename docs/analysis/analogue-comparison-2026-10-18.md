# Сравнение разбора DSL: Converter, dict2mdx и MultiConverterX

Дата: 18 октября 2026 года.

Этот анализ фиксирует состояние до последующего изменения политики диагностики. Реализованные изменения и повторный прогон Converter описаны в [дополнении](#последующее-изменение-диагностики); выводы о проверенных версиях аналогов сохранены.

На двух предоставленных архивах Python-аналог прочитал все **12 основных словарей — 750 472 статьи**. Потерянных записей и ошибок преобразования тела статьи в этом прогоне нет. Однако сокращения при прямом чтении `.dsl.dz` не загрузились. После предварительной распаковки обнаружилась другая проблема: **321 979 употреблений сокращений остались без имеющейся расшифровки из-за оформления внутри поисковой строки**. Совпадение количества записей не доказывает равенство содержимого, поисковых ключей или оформления.

В Converter после уже выполненных исправлений эти же словари также проходят полный конвейер MDX/MDD. Это результат **текущей рабочей копии**, а не опубликованной версии 0.1.0. В рамках настоящего сравнения продуктовый код не изменялся.

`dict2mdx` сам не разбирает DSL: он вызывает PyGlossary, а затем упаковщик `mdict`. Поэтому для анализа использован именно рекомендованный fork, а не современный upstream PyGlossary. [Код оболочки](https://github.com/sobaee/dict2mdx/blob/61afb0827d07b2877e29c11c0b4a82901a54443c/dict2mdx.py#L98-L129).

Граница Python-проверки — готовые **MTXT**, содержащие поисковые ключи и HTML для последующей упаковки. Python-упаковка MDX/MDD и открытие всех результатов в сторонних читалках не проверялись. Это сравнение разбора и сохранности записей, а не скорости или полной совместимости готовых словарей.

Работа выполнена изолированно в `.work/comparison/`, на существующих Python 3.10 и PHP 8.3. Глобальные зависимости не устанавливались. Исходники аналогов не правились; обёртки только задают приватные пути, запускают библиотечные API и считают результаты. Пользовательские архивы, тексты и сгенерированные словари не добавлены в Git. История установленного приложения не использовалась.

## Сокращения: почему Python почти ничего не сообщает

При отсутствующем файле сокращений Python сохраняет подпись `[p]n.[/p]` зелёным курсивом без всплывающей расшифровки. Если файл существует, но в нём нет конкретного сокращения, результат такой же. Ни один из этих случаев не создаёт предупреждения. При найденной расшифровке добавляется `title`. [Обработка сокращений](https://github.com/sobaee/pyglossaryfork/blob/a7bb34b00b16be23f75f8d9a13362d70ee1a66b2/pyglossary/plugins/dsl/transform.py#L107-L122).

Отдельная проблема — поиск сопутствующего файла. Для `name.dsl.dz` код ищет `name.dsl_abrv.dsl`, а не `name_abrv.dsl` или `name_abrv.dsl.dz`. Сжатый `_abrv.dsl.dz` также не поддерживается этим механизмом. Из четырёх синтетически проверенных сочетаний сжатого/несжатого основного файла и файла сокращений сработала только пара `name.dsl` + `name_abrv.dsl`. [Алгоритм поиска](https://github.com/sobaee/pyglossaryfork/blob/a7bb34b00b16be23f75f8d9a13362d70ee1a66b2/pyglossary/plugins/dsl/reader.py#L184-L198).

Поэтому отсутствие сообщений при прямом чтении исходных архивов нельзя трактовать как успешную обработку приложенных сокращений. В Converter распознаются обе формы файлов; отсутствующая расшифровка также не блокирует конвертацию, но сейчас создаёт отдельное диагностическое событие при каждом использовании.

### Повторный прогон после правильной подготовки файлов

Для исключения проблемы поиска `.dsl.dz` проведён второй полный Python-прогон: основные файлы и сокращения предварительно распакованы в `.dsl` без изменения исходных байтов. Результат снова **12 успешных преобразований, 750 472 записи**, без пустых тел и ошибок разбора. Загрузились все восемь имеющихся файлов сокращений: два в русском наборе и шесть в английском, суммарно 1 618 ключей с расшифровками (сумма по словарям, не глобально уникальные ключи).

Наблюдение за настоящими обращениями парсера к таблице сокращений показало:

| Результат поиска                                                                   | Употреблений |
| ---------------------------------------------------------------------------------- | -----------: |
| Всего обращений из основных словарей                                               |      871 785 |
| Расшифровка найдена                                                                |      519 389 |
| Расшифровка не найдена, сообщения нет                                              |      352 396 |
| Из них после удаления HTML-оформления строка точно совпадает с существующим ключом |  **321 979** |
| Остались без совпадения после такой нормализации                                   |       30 417 |

Причина: Python накапливает внутри сокращения и текст, и HTML оформления, а потом использует всю строку как ключ. Например, ищет `<i><font color="green">сокр. от</i>` вместо `сокр. от`. В Computer En-Ru этот конкретный случай встретился **4 699 раз**, хотя обычный ключ `сокр. от` присутствует в загруженном файле. В Converter поиск выполняется по тексту узлов сокращения без оформления.

Среди 321 979 таких несовпадений: Explanatory — 172 244, Universal En-Ru — 73 769, Universal Ru-En — 59 355, остальные — 16 611. Это **употребления сокращений, не потерянные статьи и не уникальные сокращения**. Подсчёт совпадений после удаления тегов — дополнительный анализ; выходные MTXT и поведение Python не исправлялись. Остаток 30 417 нельзя без дальнейшего разбора объявлять доказанно отсутствующим при любых правилах нормализации.

## Поведение на проблемных конструкциях

Результаты ниже получены чтением кода и отдельными синтетическими проверками. Они описывают возможности и ограничения парсеров; обнаруженный на синтетике дефект не объявляется потерей в пользовательском корпусе.

| Ситуация                                  | Python из dict2mdx                                                                              | Converter в рабочей копии                                                                |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Не найдено сокращение                     | Подпись остаётся без расшифровки; сообщения нет                                                 | Подпись остаётся; `missing_abbreviation`                                                 |
| Сокращение содержит теги оформления       | Может искать HTML вместо текста и потерять существующую расшифровку без сообщения               | Поиск по тексту без оформления                                                           |
| Не найден WAV/PNG                         | Предупреждение по уникальному имени; HTML ссылается на отсутствующий файл, ресурс не копируется | Статья сохраняется, выводится видимая отметка отсутствующего ресурса; `missing_resource` |
| Нет статьи — цели ссылки                  | Создаёт ссылку, не проверяя наличие цели                                                        | Создаёт ссылку, сверяет с индексом результата; `missing_reference`                       |
| Ссылка с `dict=`                          | Имя словаря отбрасывается; остаётся обычная ссылка                                              | Имя используется при анализе связей исходников; итоговая переносимая ссылка — `entry://` |
| Пересекающиеся теги оформления            | Прямая замена даёт пересекающиеся HTML-теги без диагностики                                     | Определённые безопасные пересечения разделяются и восстанавливаются; `repaired_markup`   |
| Незакрытый или лишний тег оформления      | Может попасть в HTML как есть                                                                   | Неоднозначное нарушение структуры может остановить конвертацию                           |
| Известные `[!trs]`, `[trs]`, `[!trn]`     | Оболочка удаляется, текст сохраняется                                                           | Например, `!trs` пока остаётся видимым неизвестным тегом с диагностикой                  |
| Неизвестный тег                           | Удаляется оболочка, остаётся текст, есть предупреждение                                         | Сохраняется исходная запись тега и текст, есть предупреждение                            |
| Необязательные части заголовка `a(b)(c)`  | Только `abc` и `a`, без `ab` и `ac`                                                             | Генерируются допустимые комбинации в пределах лимита                                     |
| Исключаемая часть заголовка `item{(}s{)}` | Поисковый ключ `items`, отображение `item(s)`                                                   | Такой же результат после уже выполненного исправления                                    |

Python не выполняет собственного восстановления корректной структуры HTML при пересечении тегов. Например, синтетическое `[b]a[i]b[/b]c[/i]` становится `<b>a<i>b</b>c</i>`. Итоговое отображение зависит от HTML-обработки читалки. [Запись закрывающих тегов](https://github.com/sobaee/pyglossaryfork/blob/a7bb34b00b16be23f75f8d9a13362d70ee1a66b2/pyglossary/plugins/dsl/transform.py#L124-L160).

Ещё один важный результат синтетики: при незавершённом `[bad` Python теряет тело статьи, пишет ошибку в журнал и продолжает работу. Затем стандартный фильтр исключает пустую статью. В проверке настоящего конвейера из двух исходных записей получилась одна, при успешном возврате `Glossary.convert`. **В 12 пользовательских словарях таких ошибок и пропусков не обнаружено.** [Обработка ошибки](https://github.com/sobaee/pyglossaryfork/blob/a7bb34b00b16be23f75f8d9a13362d70ee1a66b2/pyglossary/plugins/dsl/reader.py#L107-L133), [фильтр пустых определений](https://github.com/sobaee/pyglossaryfork/blob/a7bb34b00b16be23f75f8d9a13362d70ee1a66b2/pyglossary/entry_filters.py#L102-L109).

Синтетикой также воспроизведены зависимость `target=` от порядка атрибутов ссылки и потеря символа после неэкранированной `]`. Эти случаи — дополнительные причины проверять содержимое, а не только успешное завершение программы.

## Дополнительная проверка PHP-аналога

MultiConverterX №19 создал все 12 MDX без диагностических сообщений, но его DSL-путь значительно упрощает содержимое:

- `_abrv.dsl` не читается: даже существующие расшифровки не появляются.
- Блоки ресурсов `[s]` и URL удаляются вместе с содержимым, в том числе при наличии файла. MDD в этом пути не создаётся.
- Ссылки с `dict=` не обработаны: в реальном Universal En-Ru остались все 507 таких DSL-конструкций на Grammar.
- В том же результате остались 69 187 пар тегов транскрипции `[t]...[/t]`.
- Код ограничивает ключ 50 символами и не реализует исключение `{...}` из поискового ключа.

Таким образом, одинаковые 750 472 записи у PHP не означают равноценного преобразования. Проверен именно MDX-путь пакета, а не отдельный HTML-конвертер из того же архива. [Неизменяемая ссылка на проверенный пакет](https://github.com/dictz/php-multiconverter/blob/177593afb4dbff106fb4c767aed54f38b5e06ad1/mcx_19.zip); ключевые файлы внутри — `dsx/php/adapter_dsl.php`, `functions.php`, `convert_md.php`.

## Что имеет смысл изменить в Converter

Сейчас на этих двух архивах записано **981 805 диагностических событий**:

| Код                    | Событий | Смысл                                            |
| ---------------------- | ------: | ------------------------------------------------ |
| `repaired_markup`      | 908 017 | Оформление восстановлено, конвертация продолжена |
| `missing_abbreviation` |  30 419 | Нет расшифровки, подпись сохранена               |
| `missing_resource`     |  35 915 | Входной набор не содержит запрошенный ресурс     |
| `unknown_tag`          |   7 093 | Встречен неподдерживаемый тег                    |
| `missing_reference`    |     361 | Цель не найдена в индексе итогового словаря      |

Это события, а не число повреждённых статей. Счётчики также нельзя напрямую сопоставлять с Python: там отсутствующие ресурсы считаются по уникальным именам, а большинство остальных ситуаций вообще не диагностируется.

**Рекомендация — сделать диагностику спокойнее, сохранив проверку содержимого.** Следующие изменения предложены по результатам анализа и пока не реализованы:

1. Успешное безопасное восстановление оформления учитывать как информацию в отчёте, без статуса «с предупреждениями» только по этой причине. Оно составляет около **92,5%** текущих событий.
2. При полностью отсутствующем словаре сокращений показывать одно информационное сообщение. Если файл есть, но отдельных расшифровок нет — объединять сообщения по сокращению с числом употреблений. Исходную подпись всегда сохранять.
3. Явно поддержать известные служебные теги `!trs`, `trs`, `!trn`, сохраняя текст и учитывая их назначение в формате. Не показывать пользователю эти оболочки как неизвестную разметку.
4. Для отсутствующих ресурсов показывать сводку по уникальным файлам, а для отсутствующей звуковой коллекции — понятное общее предупреждение. В подробном отчёте сохранять места обращений. Отсутствующую озвучку восстановить из этих архивов нельзя.
5. Разделять внешнюю межсловарную ссылку и действительно отсутствующую внутреннюю статью. Разрешённые связи внутри подготовленного набора учитывать отдельно от ограничений сторонних читалок.
6. Сохранить контроль количества статей, ключей и ошибок. Не копировать поведение, при котором запись исчезает, а результат выглядит полностью успешным.

Снижение числа сообщений должно происходить за счёт уровня важности и группировки, а не пропуска статей, удаления ресурсов или отказа от проверки ссылок.

## Последующее изменение диагностики

После этого анализа в рабочей копии реализованы информационный уровень для восстановленного оформления и отсутствующего целого файла сокращений, группировка недостающих отдельных сокращений и ресурсов с числом употреблений, прозрачная поддержка `!trs`, `trs`, `!trn`. Неизвестные теги и цели ссылок продолжают проверяться; отдельная политика межсловарных ссылок и общее предупреждение о целой звуковой коллекции не добавлены.

Повторный прогон сохранил все 750 472 статьи и ключа.
